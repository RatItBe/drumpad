# 보이스 드럼패드 (가칭)

> 이 파일은 프로젝트 설명서이자 할 일 목록이다. AI는 작업을 시작하기 전에 이 파일 전체를 읽고, 작업이 끝나면 아래 TODO를 갱신한다.

## 1. 한 줄 요약

사용자가 자기 목소리나 주변 소리(박수, 페트병, 컵 두드리기 등)를 직접 녹음해 16개 패드에 채우고, 그 패드를 드럼패드처럼 두드리며 노는 웹앱.

## 2. 기술 조건

- **순수 HTML / CSS / JavaScript**만 사용한다. 빌드 도구, 프레임워크(React 등), 서버 없음.
- 파일 구조: `index.html`, `style.css`, `script.js` (필요하면 이 정도에서 늘린다)
- 외부 라이브러리는 꼭 필요할 때만, CDN으로 불러온다.
- 배포: **GitHub Pages**. 마이크는 HTTPS 주소(또는 localhost)에서만 동작하므로 `index.html`을 파일로 직접 여는 방식은 쓰지 않는다.
- 사용 API
  - 녹음: `navigator.mediaDevices.getUserMedia`, `MediaRecorder`
  - 재생·자르기·파형: Web Audio API (`AudioContext`, `AudioBuffer`)
  - 저장: IndexedDB
- 지원 환경: PC 크롬, 안드로이드 크롬, 아이폰 사파리. 마우스, 터치, 키보드 모두 지원.

## 3. 화면과 기능

### 3-1. 패드

- 4×4, 총 16개 패드. 패드끼리 역할 구분은 없다. 어떻게 채울지는 사용자 마음이다.
  (예: 8칸은 "도레미파솔라시도"를 직접 불러 건반처럼, 8칸은 박수·페트병 소리로 드럼처럼)
- 각 패드에는 대응하는 키보드 키 글자를 표시한다.
- 패드 상태는 **빈 패드 / 채워진 패드** 두 가지이며 눈으로 구분되어야 한다.

### 3-2. 키보드 배치

```
4 5 6 7
R T Y U
F G H J
V B N M
```

- **반드시 `event.code`(물리적 키 위치)로 판별한다.** `event.key`를 쓰면 한글 입력 상태에서 R이 "ㄱ"으로 들어와 동작하지 않는다.
  - 예: `Digit4`, `KeyR`, `KeyF`, `KeyV` …
- 키를 누르고 있을 때 반복 입력(`event.repeat`)은 무시한다.

### 3-3. 연주 모드 (기본 상태)

- 패드를 클릭 / 터치 / 키보드로 누르면 그 패드의 소리를 **녹음된 그대로** 재생한다 (음 높이 변경 없음).
- 누르는 순간 바로 소리가 나야 한다. 매번 새 `AudioBufferSourceNode`를 만들어 재생한다.
- 여러 패드 동시 입력(멀티 터치 포함) 가능.
- 같은 패드를 빠르게 연타하면 이전 소리를 끊지 않고 겹쳐서 재생한다.
- 누를 때 패드가 눌린 것처럼 보이는 시각 효과를 준다.
- 빈 패드를 누르면 소리 없이 살짝 흔들리는 효과만 준다.

### 3-4. 수정 모드

- 화면의 버튼으로 켜고 끈다. 켜져 있다는 것이 화면에서 분명히 보여야 한다.
- 수정 모드에서는 패드를 눌러도(클릭·터치·키보드 모두) 소리가 나지 않고, **그 패드용 메뉴**가 뜬다.
  - 빈 패드: **녹음**
  - 채워진 패드: **다시 녹음**, **구간 편집**, **위치 바꾸기**, **지우기**
- **위치 바꾸기**: 이 패드를 고른 뒤 다른 패드를 누르면 두 패드의 소리가 서로 자리를 바꾼다. 빈 패드를 고르면 그 자리로 이동한다. 취소할 수 있어야 한다.
- 수정 모드일 때만 **전체 초기화** 버튼을 보여준다. 누르면 "정말 모두 지울까요?" 확인을 한 번 거친다.

### 3-5. 녹음

- 녹음 시작 / 정지 버튼. 녹음 중임이 화면에 분명히 보여야 한다 (예: 빨간 표시, 경과 시간).
- 최대 녹음 길이는 5초로 하고, 넘으면 자동으로 정지한다.
- 녹음이 끝나면 바로 패드에 넣는다.
- 마이크 권한이 거부되면 이유와 해결 방법을 안내하는 메시지를 보여준다.

### 3-6. 구간 편집 화면

- 녹음된 소리 **전체**의 파형을 보여준다.
- 시작점·끝점을 나타내는 왼쪽 / 오른쪽 막대. 처음에는 양 끝에 놓여 있다.
- 막대는 마우스 드래그와 터치 드래그 모두로 옮길 수 있다. 시작점이 끝점을 넘을 수 없다.
- 아래에 **재생**(선택 구간만 미리듣기), **저장**, **취소** 버튼.
- **원본 녹음은 지우지 않고, 시작점·끝점 정보만 저장한다.** 나중에 막대를 다시 넓히면 잘렸던 부분이 되살아나야 한다.

### 3-7. 저장

- 각 패드의 원본 녹음 데이터, 시작점·끝점, 패드 위치를 IndexedDB에 저장한다.
- 새로고침하거나 브라우저를 다시 열어도 그대로 복원되어야 한다.
- 가능하면 `navigator.storage.persist()`로 영구 저장을 요청한다.
- 브라우저마다 녹음 형식이 다르다 (크롬은 webm, 사파리는 mp4). 녹음 파일(Blob)을 그대로 저장하고, 불러올 때 `decodeAudioData`로 해석한다.

### 3-8. 브라우저별 주의점

- 아이폰 사파리는 사용자가 화면을 한 번 터치하기 전에는 소리가 나지 않는다. 첫 화면에 **시작하기** 버튼을 두고, 눌렀을 때 `AudioContext`를 시작(`resume`)한다.
- 모바일에서 패드를 빠르게 두드릴 때 화면 확대, 텍스트 선택, 길게 누르기 메뉴가 뜨지 않게 막는다 (`touch-action`, `user-select` 등).
- 터치와 마우스 이벤트가 중복으로 들어와 소리가 두 번 나지 않게 한다 (Pointer Events 사용 권장).

## 4. 이번 버전에서 하지 않는 것

- 시퀀서 (박자 격자에 찍어서 반복 재생)
- 키트 내보내기 / 불러오기
- 키 배치 바꾸기
- 피치 조정, 멜로디 모드
- 서버, 로그인, 공유

## 5. AI 작업 규칙

- 한 번에 TODO 한 단계씩 작업한다. 요청받지 않은 기능은 추가하지 않는다.
- 작업이 끝나면 무엇을 바꿨는지, 브라우저에서 어떻게 확인하면 되는지 짧게 알려준다.
- 작업이 끝나면 이 파일의 TODO를 갱신한다: 끝난 항목은 `[x]`로 체크하고, 작업 중 발견한 버그나 필요한 일은 알맞은 단계에 새 항목으로 추가한다.
- 이 파일의 기능 설명과 다르게 구현해야 할 이유가 생기면, 마음대로 바꾸지 말고 먼저 물어본다.
